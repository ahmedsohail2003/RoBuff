UB Hacking 2026 · Deep space

Pick up a space rock with your bare hand, using only friction, after a lift test passes. with your bare hand.

A signal takes 2.56 s to reach the Moon and come back. In a 2024 University of Bristol study, people steering a robot arm with delays up to 2.6 s did worse on every measure. RoBuff lets you steer a simulated robot arm with your hand through a webcam. The arm grips by friction, and a see-through ghost arm shows where it is heading. It works with a real hand on a laptop webcam. In 5 of 5 logged runs with a scripted hand, the cube rose 78.4 mm.

How your hand controls the arm.
Find the hand, turn it into a command, move the arm.

The hand-to-arm loop runs in your browser. The arm is a free, public robot model called the SO-ARM100, inside a physics simulation. No real robot is attached. In Moon mode, every move and every frame is delayed 1.28 s each way, like a real Earth-to-Moon link. A see-through ghost arm shows where the arm is heading. I have not measured yet whether the ghost helps people.

Ask for an object

You type a request. When a key is set, Gemini, Google's AI model, turns it into an object description. Without a key, an offline parser does this. The app then builds a 3D model from it. Before the object appears, 7 checks decide whether the arm could hold it.

Every refusal shows the numbers behind it.

A generated object is only useful if the arm can hold it. So the app checks every request first. Then it places the object and runs a simulated lift test. If the lift fails, the object is removed. The tools I used. What each one is, and why I needed it.

MuJoCo

Working

A physics engine that works out contact and friction. I run it in the browser so a rock rises only if friction really holds it.

MediaPipe Hand Landmarker

Working · tried with a real hand

Google's hand-tracking model. It finds 21 points on a hand in each camera frame. It runs on the laptop, so no video is uploaded. It took a median 11 ms per frame on Chrome's fake camera.

SO-ARM100 from MuJoCo Menagerie

Working

A small open-source robot arm with 5 joints and a jaw. The model comes from MuJoCo Menagerie, a library of checked robot models. I used it as published, with no changes.

Playwright and Vitest

Working

These are automated test tools. Playwright drives a real Chrome browser from a script, so anyone can re-run the scripted pick, the fake camera and the object requests. Vitest tests the physics, the filters and the checks without a browser. 201 of 201 tests passed.

Gemini 3.8 Flash

Working (format check 5 / 5)

Google's AI model. It turns a typed request into an object description (kind, size, material) that the checks can test. A small server holds the API key, so the key never reaches the page. In a live test, 5 of 5 replies came back in the right format, with a median of 3867 ms. That test only checked the format. The sizes it returned did not always match the request.

The ghost arm (a predictive display)

Built · result not measured

A second simulation runs your commands with no delay. It draws a see-through arm where the real arm is heading. ROTEX flew this idea in 1993. Whether it helps people is not measured yet.

Voice is hold-to-talk. It uses the browser's speech recognition and an offline list of commands. ElevenLabs is a text-to-speech service. When its key is set on the local key server, it gives the console a natural voice. In a live check, 5 of 5 lines came back as audio, and the first audio arrived after a median 176 ms. Without the key, the browser's built-in voice speaks instead, and the screen says it is offline. Captions are always on. Without a Gemini key, an offline parser reads requests instead, and the screen says so.

The app's hard limits for objects are 10 to 70 mm wide and up to 300 g. I set them with a safety margin from grasp tests on the simulated arm. For steering by hand, the app uses tighter limits of 15 to 55 mm and 200 g. I chose these from a review of my earlier SO-ARM100 projects. I have not re-measured them with real-hand control yet. The calculator and the refusals use these tighter limits. The payload of a real SO-ARM100 is not verified.

I wrote every line of app code during UB Hacking 2026. The first commit is at 1:43 PM EST on November 7. Hacking opened at 1:30 PM.

My earlier related projects are the WorkCell series, EmberHacks "The cell", HandSignal and FleetLine. No code from them is reused here. While planning, I read their repositories for facts only, such as arm limits and package names. I copied nothing. What carries over is my experience, the same public arm model and the same hand-tracking library.

Arm model: MuJoCo Menagerie SO-ARM100 (trs_so_arm100, Apache-2.0), from The Robot Studio's SO-ARM100. Physics: MuJoCo. Hand tracking: Google MediaPipe hand landmarker. Rendering: three.js. Page background: three.js (MIT), with a procedurally drawn Moon and starfield, illustrative only. Gravity and distance data: NASA NSSDC fact sheets and JPL's small-body database. Predictive-display idea: MIT (Sheridan 1984) and JPL (Bejczy, Kim and Venema 1990), flown on DLR's ROTEX in 1993. Delay study: Louca et al. 2024, University of Bristol, ACM Transactions on Human-Robot Interaction, doi:10.1145/3651993. Page layout inspired by ZELT (zelt-nu.vercel.app).

I planned, coded and tested this with Claude Code, Anthropic's AI coding assistant. I directed and reviewed the work. Inside the app, the MediaPipe hand landmarker runs in the browser, and Gemini 3.8 Flash reads typed object requests when a key is set on the key server.
